## 产品目标

同一个网站包含两个主要入口：面向读者的个人博客，以及面向本人和 AI 工具的记忆库。博客负责完整文章；记忆库负责能够追溯来源、纠正和再次使用的知识、偏好、项目决定与经验。

## 三种可实施的方案

| 方案 | 保存位置 | 能力 | 取舍 |
| --- | --- | --- | --- |
| 公开博客与公开记忆 | Git 仓库中的 Markdown 和 JSON | 文章发布、记忆浏览、全文搜索、公开机器可读索引、版本历史 | 所有提交的内容都公开；网页编辑后的保存需要经过 Git 发布流程 |
| 公开博客与本机私有记忆 | 公开内容在 Git；私有对话和记忆在浏览器本地数据库 | 粘贴或导入对话、记忆编辑、搜索、上下文导出、备份、选定笔记公开 | 不需要新增后端；私有内容不自动跨设备同步，需导出备份 |
| 公开博客与云端私有记忆 | 公开内容在 Git；私有内容在鉴权数据库 | 登录、设备同步、私有检索、服务端 AI 接入 | 需要额外服务账户、部署与访问规则；GitHub Pages 只承担前端 |

已选择第二种：公开博客与本机私有记忆。首版不连接模型接口，不提供登录或云同步。公开博客由 Git 管理；记忆工作台仅在当前浏览器保存。选定记忆可导出 Markdown 供用户审阅并提交为公开内容，网页不持有 GitHub 写入令牌。

## 共同的博客设计

- 中文优先的个人首页，展示个人简介与最新文章。
- 文章列表和详情、归档、标签、关于页面。
- Markdown 内容来源，代码高亮，目录，明暗主题，移动端与键盘访问。
- 全文搜索、RSS/Atom 与站点地图。
- 保留《关于》的正文、2024-11-02 日期与 /post/about/；保留 /archives/、/tags/、/atom.xml 以及现有头像和图标；空列表提供明确的空状态。
- 使用 Astro 静态构建，通过 GitHub Actions 部署到现有地址。

## 共同的记忆设计

1. 对话记录：保存标题、来源、日期、角色和消息正文。首版支持粘贴文本及明确版本的通用 Markdown/JSON 导入；平台专用导出格式在获得真实样本后适配。
2. 记忆卡片：记录经本人确认的偏好、事实、项目决定和经验，含标签、项目、更新时间及来源对话/消息标识。
3. 可纠正：修改、删除、标为过期，避免旧记忆长期混入上下文。
4. 可检索：按关键词、标签、项目与日期过滤，对话与记忆互相链接。
5. 可带走：导出包含来源和更新时间的 Markdown/JSON；选中相关记忆生成可复制的 AI 上下文。
6. 可公开：公开方案直接生成可读页面和机器可读索引；混合方案仅通过本人明确选定的发布流程生成公开内容。

首版 AI 使用方式为检索和选择有效记忆，然后复制/导出上下文给新对话。记忆摘要由本人编辑确认。没有后台自动访问原始聊天或自动调用模型；界面不要求模型密钥。

## 数据流

对话粘贴/导入 → 对话记录 → 编辑并确认记忆卡片 → 搜索与筛选 → 导出 AI 上下文，或选定内容发布为博客/公开记忆。

公开文章与记忆的构建过程只读取明确的公开内容来源。私有数据库不参加静态构建，不进入公共搜索索引或公共 Feed。

## 错误处理与验收

- 无效导入给出错误位置，不覆盖现有数据；重复导入有明确去重规则。
- 导入的文本按文本/经过清理的 Markdown 显示，不能执行其中的脚本。
- 备份导出再导入保留对话、记忆、标签和来源引用。
- 新页面可在移动端与键盘下使用，旧链接仍到达对应内容。
- 搜索能找到中文内容；过期记忆默认不进入导出上下文。
- 静态构建和类型检查通过；核心数据导入、来源关联、筛选、导出往返有实际测试。
- 私有方案必须验证公共输出中没有私有测试内容；云端方案另验证未授权请求不可读写。
